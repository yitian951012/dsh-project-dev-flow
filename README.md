# 项目开发流程（dsh-project-dev-flow）

一个面向 DSH 的开发流程插件，把「需求 → 设计 → 开发 → 验证 → 交付 → 复盘」整套工程习惯带进对话里。

安装后，DSH 会多出三个入口：
1. **会话模式「项目开发流程」**：按阶段推进任务，要求每条结论都附带命令输出、文件路径等实际证据，不替你拍板或签字。
2. **输入框快捷按钮**（`3.0.1`）：在任意会话输入框左侧点开，可一键新建流程会话，或把 5 个阶段技能的 `/命令` 插入草稿。
3. **侧栏「项目看板」**（`3.0.0`）：只读展示项目的阶段进度、待办、待裁决与阻塞项，数据直接从项目 `docs/` 文档派生。

> 本插件只是流程助手，不替代项目自己的工程文档，也不会强制拦截你的操作；真正的门禁仍在项目的测试、CI 与人工确认上。

---

## 1. 快速开始

### 环境要求

- **DSH**：`>=0.2.3-alpha.2 <0.3.0-0`（已校验运行时：`0.2.3-alpha.2`；`0.2.2` 系列不支持侧栏看板入口）
- **Node.js**：`^24.22.3 || >=26.13.1`（`24.x` 需 `24.22.3` 及以上，或 `26.13.1` 及以上）

### 安装

- **体验 3.0.x（含项目看板与输入框入口）**：目前 `3.0.x` 尚未发布到 npm，请在 DSH 的 Plugins 面板选择「本地目录安装」并指向本包目录，或通过 GitHub 源安装：
  ```bash
  dsh plugin --profile <profile> add github:yitian951012/dsh-project-dev-flow
  ```
- **从 npm 安装稳定版（2.1.3，不含看板与输入框入口）**：
  ```bash
  dsh plugin --profile <profile> add @yitian951012/dsh-project-dev-flow
  ```

> **升级提示**：从 `2.x` 升级到 `3.0.x` 时，请先卸载旧版本再安装新版本；已经开启的旧会话会保留原来的模式，需要**新开一个会话**才会看到新工具和完整功能。

### 三步用起来

1. 在 DSH 的 Plugins 面板启用本插件。
2. 新建一个会话，在模式选择器中选择 **「项目开发流程」**（或在已有会话里点击输入框左侧的流程图标新建）。
3. 直接描述你要做的事，或输入 `/project-` 选择对应阶段的技能。

## 2. 功能介绍

### 2.1 输入框快捷入口（3.0.1）

在会话输入框左侧工具行中，点击流程图标会弹出一个快捷面板，包含两项功能：

- **新建流程会话**：点击后二次确认即可开启。如果当前是还没发过消息的空白会话，会直接把当前会话切换为「项目开发流程」模式并保留草稿；如果已有对话记录，会新开一个流程会话并把当前草稿复制过去（附件不会随行，也不会自动发送）。
- **插入阶段技能**：点击下方任意技能，会把对应的 `/命令` 插入到输入框第一行，方便你在发送前补充具体要求。
  - 仅在已启用「项目开发流程」模式的会话中可点；在普通会话中会自动禁用，避免发出无效命令。

> 面板不会替你发送消息，也不会在这个弹窗里打开看板（看板请从侧栏进入）。

### 2.2 五个阶段技能

插件内置 5 个技能。前 3 个会在对话中由模型根据场景自动调用，后 2 个涉及验收判定与复盘归档，只能由你通过 `/命令` 手动触发：

| 技能命令 | 适用场景 | 触发方式 |
| :--- | :--- | :--- |
| `/project-dev-flow` | 接手新项目、梳理全局流程、按阶段推进开发 | 自动 / 手动 |
| `/project-intake` | 提新需求、调整范围、变更接口契约或验收标准 | 自动 / 手动 |
| `/project-docs` | 文档散乱、需要建立索引或排查文档与代码不一致 | 自动 / 手动 |
| `/project-acceptance` | 准备交付、核对验收清单、检查证据是否齐全 | 仅手动 |
| `/project-case-distill` | 将一次真实交付或排障过程沉淀为复用案例 | 仅手动 |

使用示例：`/project-acceptance 帮我核对这次版本是否满足交付条件`

### 2.3 侧栏项目看板（3.0.0，只读）

侧栏的 **「项目看板」** 会读取工作区 `.dsh/project-board/board.json`，按阶段或状态展示待办、待裁决和阻塞问题，同时为 Agent 提供只读查询工具 `project_board`。

> 3.0.x 版本的看板为**只读视图**，不会反向修改你的 `docs/` 文档；拖拽改状态等写操作计划在 `3.1.0` 提供。

#### 生成或更新看板数据

```bash
# 从项目 docs/ 派生看板数据（只识别匹配表头的台账，不会编造数据）
node scripts/import-board.mjs --root <项目绝对路径>
```

如果新项目还没有 `docs/` 目录，可以在看板的「绑定项目」弹窗中勾选自动生成基础台账，或手动执行：

```bash
# 生成 5 份最小基础台账（已存在的文件会自动跳过）
node scripts/scaffold-docs.mjs --root <项目绝对路径> --write
```

#### 管理多个项目

- **面板绑定（推荐）**：直接在看板顶部的项目切换器里选择目录并绑定，配置保存在用户 profile 的 `plugin-data` 中，升级插件不会丢失。
- **手写配置（可选）**：也可以在 `<profile>/cordis.patch.yml` 中按如下格式声明（请勿写进插件包内的 `cordis.patch.yml`）：

```yaml
- id: project-dev-flow-board
  name: '@yitian951012/dsh-project-dev-flow'
  config:
    projects:
      - root: E:/dsh-workspace/项目管理
      - root: D:/work/other-project
        docs: spec   # 可选：自定义文档目录名
```

#### 自定义阶段映射（可选）

如果项目需要固定表格映射或将条目归类到指定阶段，可运行自检并生成 `.dsh/project-board/manifest.json`：

```bash
node scripts/adapt-project.mjs --root <项目绝对路径>          # 只读检查
node scripts/adapt-project.mjs --root <项目绝对路径> --write  # 写入映射清单
```

看板按 `docs/` 中识别到的阶段与门禁节点自动生成行（无节点时使用默认的 8 阶段 + 2 门禁），未归属到具体节点的条目不会强行显示为「未归属」行。

## 3. 使用边界

1. **项目自身规范优先**：如果目标项目已有自己的工程手册或同名技能，以项目自身的为准。
2. **重大决策与签认归人**：范围变更、契约调整与最终验收签字只能由人决定，Agent 只负责整理和起草。
3. **如实报告未验证项**：没有可用测试命令或未实际跑通的检查，会直接标注「未验证」，不会用猜想代替。
4. **工具面说明**：插件默认关闭了定时任务工具（`tool-schedule`），如需开启可在 `cordis.patch.yml` 中移除对应的 `disabled: true`；工作流编排与子代理相关工具由宿主控制，如需关闭请在宿主 profile 中配置。

## 4. 目录结构与维护（开发者参考）

```text
dsh-project-dev-flow/
├── index.js              # Host 端入口：注册 project_board 工具与看板接口
├── client/client.js      # Web 端入口：侧栏看板与输入框快捷面板
├── cordis.patch.yml      # 插件配置：声明 preset 与挂载包内技能
├── skills/               # 5 个技能及参考资料
├── methods/              # 5 份通用工程方法（按节读取以节省上下文）
├── templates/            # 9 份通用文档模板
├── cases/                # 3 份参考案例
├── schema/ & scripts/    # 数据校验、看板导入、脚手架与发布检查脚本
└── tests/ & evidence/    # 单元测试与各版本发布验证记录
```

常用开发与检查命令：

```bash
npm ci                                  # 安装开发依赖
npm run verify                          # 运行全量检查（包结构、来源、patch、测试、打包）
npm run smoke:profile                   # 在隔离 profile 中测试安装与卸载
npm run acceptance -- --profile <name>  # 真实会话验收（需 profile 已配置模型凭据）
node scripts/section.mjs <方法名> 2 3   # 按节读取方法文档的 §2–§3
```
