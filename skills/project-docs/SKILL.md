# 项目文档治理

## 何时使用

- 文档数量增加，同一结论出现在多处，没人知道该信哪一份。
- 文档与代码行为不一致，需要判定改文档还是改代码。
- 需要迁移、合并、归档一批文档，或建立/修复唯一索引。

## 输入

- {{doc:root}} 下的文档清单与各自头部元数据（用途、owner、最后复核日期）。
- {{doc:index}} 现状与生命周期登记现状。
- 代码与命令入口（用于当场核对文档声称，不作判据替代）。

## 步骤

1. 先加载 `../../methods/truth-and-lifecycle.md`；层级判定细则见 `references/doc-lifecycle-map.md`，归属或层级变更需登记时按 `../../methods/intake-and-decision.md`。
2. 建清单：逐个记录用途、owner、最后复核日期、被谁引用；无 owner 的文档单列。
3. 归三态：活（可作为当前判定依据）/ 史（只讲当时）/ 档（仅溯源）；判定表见 references。
4. 立唯一索引：{{doc:index}} 每行 = 文档 + 性质（活/史/档）+ 定位 + owner + 复核到期日；同一结论只允许一个归属。列名以 `../../templates/docs-index.md` 为准。
5. 查重复与断链：重复结论指定唯一归属，其余改为链接；失效链接逐个修正或标档；按 `references/drift-audit.md` 执行。
6. 查漂移：用 {{command:verify}} 或 {{command:test}} 的当场输出核对文档声称；不一致时按事实源分权判谁错（实现事实 → 改文档；授权决策 → 改代码或改判据）。
7. 登记生命周期：把层级、复核日期写入登记；史档文档加「不参与当前判定」头注。
8. 迁移或合并只允许「索引 + 登记 + 正文」同批更新，禁止只改其中一处。

## 输出

- 文档清单表：层级、owner、复核日期、被引用处。
- 归属决定：哪些结论唯一归于哪份文档，哪些降为链接。
- 漂移与断链清单：证据（命令 + 输出摘要）与处置结论。
- 需 {{role:owner}} 或 {{role:approver}} 复核的争议项。

- 产出一份 [文档唯一索引](../../templates/docs-index.md) 表与生命周期登记变更。

## 停止条件

- 每份文档都有唯一层级与 owner，索引与登记一致 → 可交付。
- 漂移项已分类（改文档 / 改代码 / 待裁决），且无未分类项。
- 归属有争议 → 停在 {{role:approver}}，不自行裁定。

## 常见错误

- 直接合并正文而不更新索引与登记。
- 把历史文档当现状引用，或用历史结论否掉当场证据。
- 索引与正文两处维护同一结论，随后自然发散。
- 以「看起来对」判定漂移，不跑命令。
- 擅自删除历史归档，或改写历史结论。
