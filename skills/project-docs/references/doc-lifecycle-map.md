# 文档三态判定表

> 用途：层级决定一份文档能不能被当作「当前判定依据」。判错层级，后面所有引用都失真。

## 三态定义

| 层级 | 判定标准 | 可被当前结论引用 | 处置 |
| :--- | :--- | :--- | :--- |
| 活 | 描述仍在生效的规则、契约、判据；有 owner 与复核日期 | 是 | 维护正文，随代码同批更新 |
| 史 | 记录某时段的判断、进展、事故；结论已不再作为现状 | 否（只可作背景） | 加「不参与当前判定」头注，冻结正文 |
| 档 | 仅用于溯源，正文被新文档取代 | 否 | 保留链接，不再更新 |

## 判定四问

1. 结论现在还能否被执行或复核？（能且需维护 → 活）
2. 正文是否绑定某个时点的事实（当时的命令输出、当时的取舍）？（是 → 史）
3. 是否已有文档承接它的结论？（是 → 档）
4. 有 owner 且复核日期未过期？（否 → 先补 owner 再定层级）

## 边角规则

- 一份文档可以「主体为活、附录为史」：附录单独标注层级，不整篇降级。
- 活文档过期未复核：先标「待复核」，不得升为判定依据，也不直接降为史。
- 判定结果冲突时按事实源分权：范围与判据看决策登记，实现与数字看当场命令，其余看项目手册。
- 层级变更必须同时写进生命周期登记；只改正文头注视为未登记。

## 反例

- 把进展流水当活的现状（流水天然是史）。
- 把历史事故分析当判据依据，用「上次就是这样」否掉当场复现。
- 给史档文档补新数字，让它看起来「仍有效」。

## 索引行格式

- 文档相对路径 + 标题 + 层级 + owner + 复核日期 + 一句话用途。
- 一个结论只允许一行是「归属行」，其余行指向它，不得并列维护。
