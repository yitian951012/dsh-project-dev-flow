# 漂移与断链审计

> 用途：文档治理里唯一需要跑命令的环节。目标是判定「谁错」，不是改文档让它看起来对。

## 漂移类型

| 类型 | 现象 | 判定依据 | 默认处置 |
| :--- | :--- | :--- | :--- |
| 实现漂移 | 文档描述的行为与当次命令输出不一致 | {{command:verify}} / {{command:test}} 输出 | 文档错 → 改文档 |
| 判据漂移 | 文档判据已被决策登记改动 | {{doc:decision-log}} | 文档错 → 改文档并标注决策编号 |
| 代码漂移 | 代码未实现已登记决策 | 决策登记 + 当场证据 | 代码错 → 记入残余问题，不擅自改判据 |
| 投影漂移 | 看板与事实源不一致 | 事实源 | 改看板，不改事实源 |
| 措辞漂移 | 同一概念多处叫法不同 | 项目手册术语表 | 统一到手册术语，其余改链接 |

## 审计顺序

1. 先冻结范围：本轮只审哪些文档、哪些结论，避免无限扩张。
2. 跑一次 {{command:verify}}（或项目约定的等价命令），记录 exit code 与 {{commit:head}}。
3. 逐条把文档声称与输出对齐，能对齐的打「一致」，对不齐的按上表分类。
4. 分类完成后再动手改一处，改完复跑同一命令，确认不是改出新漂移。
5. 结论写进漂移清单：文档锚点、证据摘要、处置、责任人。

## 断链处理

- 目标文档已改层级：改链接指向承接文档，并在原处留一行「已迁移至 X」。
- 目标文档已删除且无承接：补一条索引行或直接重建承接文档，不让链接悬空。
- 跨层级链接（活 → 史）：链接保留但加注「历史，不参与当前判定」。

## 禁止

- 为让文档与代码一致而改测试、改判据、改守卫。
- 用「上次跑过」的旧输出作为本次漂移判定依据。
- 审计中顺手重写无关章节，制造第二处漂移。
