# 受理单字段与判据写法

> 用途：受理单是后续所有证据的锚点。字段缺失，验收就无法复核。

## 必填字段

| 字段 | 要求 | 缺了会怎样 |
| :--- | :--- | :--- |
| 目标 | 一句话，动词开头，单一结果 | 验收无人可判 |
| 非目标 | 显式列出本批不做什么 | 范围在实现中扩散 |
| 验收判据 | 逐条编号，可执行或可观察 | 只能靠印象判定 |
| 判据归属 | 每条判据属于哪一层（单测/接口/端到端/人工） | 用错层证明，结论不可信 |
| 证据口径 | {{evidence:ttl}} 与重跑条件 | 过期证据被当现状 |
| 影响面 | 契约、数据、文档、守卫 | 漏改一处即回归 |
| 风险与依赖 | 外部依赖、撞车面、回滚方式 | 失败后无法止损 |
| 批次拆分 | 最小可独立验证单元 | 大批次无法定位红因 |
| 决策需求 | 是否需要登记及签认人 | 事后追溯断裂 |

## 判据写法：正例

- 「调用 {{command:test}} 且目标用例由红转绿，exit code = 0。」
- 「对同一输入重复执行两次，可观察输出一致。」
- 「{{command:verify}} 在 {{commit:head}} 上 exit code = 0，且无新增告警。」
- 「删除临时目录后重跑，结果不变。」（幂等性）

## 判据写法：反例与改法

| 反例 | 问题 | 改法 |
| :--- | :--- | :--- |
| 体验流畅 | 不可判定 | 给出可观察量：交互步数或失败提示是否出现 |
| 性能可接受 | 无阈值 | 写明「在给定输入规模下，命令输出不超过约定阈值」 |
| 已修复 | 无证据 | 改为「原失败用例转绿 + 最小复现步骤不再复现」 |
| 全部通过 | 无范围 | 列出具体判据编号集合 |
| 文档已更新 | 无锚点 | 写明文档锚点与章节，且与代码同 commit |

## 判据自查三问

1. 换一个 agent 只看判据，能否独立复现结论？（不能 → 判据不完整）
2. 判据红了，能否一眼看出是判据写错还是实现错？（不能 → 归属未写清）
3. 判据能否在同 commit 上一次性跑完？（不能 → 拆批次）
