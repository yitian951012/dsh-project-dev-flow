# 复盘与案例提炼

## 何时使用

- 一段交付或一次事故刚结束，判断值得沉淀为可复用经验。
- 需要回答「这个方法为什么值得采用、它在哪里失败过」。
- 需要把历史材料提炼进方法库，但又不希望把单个项目的取舍当通用规则。

## 输入

- 事件时间线与当时的判断（含错误判断），越具体越好。
- 当时的可观察证据：命令类型、结果量级、时间；不要求真实数字以外的来源信息。
- 修复过程与修复后仍存在的风险。
- 拟挂接的方法文档（{{doc:index}} 中登记的现行方法）。

## 步骤

1. 方法按节读：`node <技能base>/../../scripts/section.mjs history-and-cases 2 3`（不要用读文件工具整份读，同一文件本会话不重复读）；七段结构见 `references/case-structure.md`。
2. 先写「当时的错误判断」。写不出这一段的，不写案例——只写最佳实践的案例价值为零。
3. 列候选方案与实际取舍，说明约束是什么、为什么排除了其他方案。
4. 证据只写类型与量级：命令类型、结果量级、时间；不写主机信息、账号、凭据、可识别业务数据。
5. 提炼一条可复用判断：触发条件 + 做法 + 反例；不做成一串口号。
6. 写不可外推边界：在什么约束之外这套做法失效，边界写法见 `references/distill-boundaries.md`。
7. 脱敏：真实名称统一写「来源项目（下称 P）」；删除路径、主机、端口、账号、真实作品名。
8. 与包内方法互链：结论挂到对应方法文件（受理与决策、设计与守卫、证据与验收、事实源与生命周期、历史与案例共五份），不复述其全文；历史结论只作背景，不得被写成现状。

## 输出

- 一份七段案例：背景与约束 / 错误判断 / 取舍 / 可观察证据 / 残余风险 / 方法 + 不可外推边界 / 互链。
- 缺失证据清单：哪些环节当时没留证据，导致结论只能到「存疑」。
- 脱敏自查结论（逐项打勾，不写「已脱敏」了事）。

- 产出一份 [案例卡](../../templates/case-card.md)。

## 停止条件

- 七段齐全，且第 2 段与第 6 段非空 → 可落盘。
- 第 2 段或第 6 段写不出 → 只输出「缺第 X 段」，不落盘、不伪装成案例。
- 脱敏自查有未通过项 → 停在脱敏，不进入方法互链。

## 常见错误

- 只写成功路径，不写当时的错误判断。
- 不写不可外推边界，把一个项目的取舍写成通用规则。
- 把案例写成规范条文，失去「在哪里失败过」的信息。
- 保留可识别信息（真实路径、账号、作品名、客户名）。
- 引用历史结论当现状，或用历史数字否定当场证据。
- 缺少证据时仍给「已证实」结论，而非「存疑」。
