# 证据链要素

> 用途：定义「一条可复核的通过」的最小结构。缺要素即降级，不靠语气判断。

## 最小要素（全部必需）

| 要素 | 写法 | 缺失后果 |
| :--- | :--- | :--- |
| 判据编号 | 与受理单一致 | 无法对应验收行 |
| 命令原文 | 可整段复制执行，不含省略 | 无法复现 |
| exit code | 数值 | 无法判定成败 |
| 提交 | {{commit:head}} | 证据与代码脱钩 |
| 时间 | {{date:today}} 或执行时刻 | 无法判过期 |
| 输出摘要 | 关键行或计数，不整段粘贴 | 无法核对口径 |

## 结论取值

- `通过`：要素齐全且 exit code 符合判据预期。
- `失败`：要素齐全但结果不符；附最小复现。
- `未验证`：要素不全、命令未配置或无法执行。
- `降级验证`：用替代手段验证（如只跑子集、只做静态检查），须写明降级原因与未覆盖部分。

## 投影规则

- 验收行是单项状态的事实源；看板只是投影，两者冲突以验收行为准。
- 一条判据只能有一个当前结论；旧结论保留但标注被哪条证据取代。
- 证据过期（超过 {{evidence:ttl}}）不自动失效为「失败」，而是回到「未验证」。

## 反例

- 「跑了，全绿」——无命令、无 exit code。
- 「和上次一样」——跨 commit 借用证据。
- 「开发环境手动点过」——无命令原文与可复现步骤，只能记「人工观察」。
- 粘贴整段冗长日志代替输出摘要，导致无法定位关键行。
