# 0 适配 + 六阶段（1–6）路由表

> 用途：用「进入条件 + 退出证据」判定当前阶段，而不是凭任务标题猜。
> 阶段 4/5/6 的技能默认不可自动加载（用户技能），只能提示用户显式调用；未调用时按 methods 判据执行并标注「技能未加载」。

| 阶段 | 名称 | 进入条件 | 退出证据（缺一不算退出） | 路由 |
| :--- | :--- | :--- | :--- | :--- |
| 0 | 适配 | 进入陌生项目，或 profile 过期 | profile 字段表已给出处，未验证项已列出 | 本技能 |
| 1 | 需求受理 | 有新需求、变更、缺陷反馈 | 受理单含目标/非目标/判据，判据可执行或可观察 | `project-intake` |
| 2 | 设计定型 | 范围、契约、数据、判据将变 | {{doc:decision-log}} 已登记，且写明影响面 | 本技能 |
| 3 | 实现 | 判据已定，代码待改 | 先失败后通过的用例 + {{command:test}} exit code | 本技能 |
| 4 | 验证 | 实现完成，需判定逐条判据 | 每条判据：命令 + exit code + {{commit:head}} | 提示 `/project-acceptance`；未调用则按方法执行并标注 |
| 5 | 交付 | 验收行齐备，准备交接 | 验收记录 + 剩余风险 + 签认待办 | 提示 `/project-acceptance`；未调用则按方法执行并标注 |
| 6 | 复盘沉淀 | 交付结束或出过事故 | 案例七段齐全且脱敏自查通过 | 提示 `/project-case-distill`；未调用则按方法执行并标注 |
| — | 文档治理 | 整理、审计、迁移、合并文档 | 索引与生命周期登记一致，漂移项已分类 | `project-docs` |

## 判定顺序

1. 先问「这次任务的产出物是什么」：文档 → 文档治理；判断结论 → 验证或复盘；行为变化 → 实现。
2. 再问「判据是否已存在且可执行」：否 → 回到阶段 1/2；是 → 阶段 3 起。
3. 最后问「是否已有当场证据」：无 → 阶段 4；有且需交接 → 阶段 5。

## 允许回退

- 验证红 → 回阶段 3；若红因判据本身写错 → 回阶段 2 并登记决策，不直接改判据迁就实现。
- 实现中发现范围扩大 → 回阶段 1 重受理，禁止在实现中扩范围。
- 交付前发现判据不可观察 → 回阶段 1，把判据改成可观察形式。

## 禁止跳步

- 0 → 3：profile 未验证就实现，后续所有「通过」无基准。
- 1 → 5：无判据直接交付，验收行无法复核。
- 3 → 5：无验证直接交付。
- 6 → 任何当前判定：历史结论只能作为背景，不能作为现状证据。
