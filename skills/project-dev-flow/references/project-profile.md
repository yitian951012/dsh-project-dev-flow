# 项目 profile 字段表

> 用途：把「这个项目自己的工程协议」变成可核对的结构化事实。每个字段必须有出处；无出处即未验证。
> **填写格式以 `../../templates/project-profile.md` 为唯一来源**：本文件只补充字段语义与出处规则，不另立字段集。

## 字段

| 字段 | 含义 | 出处（任选其一，须可复核） |
| :--- | :--- | :--- |
| 验证命令 | 本地全量检查入口 | 脚本清单、CI 配置、项目手册 |
| 测试命令 | 单测/集成入口与过滤方式 | 脚本清单、测试配置 |
| 构建命令 | 构建或打包入口 | 脚本清单、CI 配置 |
| 端到端命令 | 端到端用例入口 | 脚本清单、项目手册 |
| 文档根 | 项目自己的文档目录 | 索引文档、目录结构 |
| 索引文档 | 唯一文档入口 | 项目手册、目录结构 |
| 决策登记 | 决策/ADR 登记位置 | 项目手册、目录结构 |
| 状态投影 | 看板或进度文档 | 项目手册 |
| 验收清单 | 逐条判据与验收行所在 | 项目手册、验收文档 |
| 决策人角色 | 谁签认范围与判据变更 | 项目手册、用户口述（须标注） |
| 验收人角色 | 谁签认交付 | 项目手册、用户口述（须标注） |
| 证据有效期 | 多久后证据需重跑 | 项目手册、团队约定（须标注） |
| 禁用操作 | 需要人工授权或禁止的操作 | 项目手册、守卫配置 |

## 填写规则

1. 一个字段只能有一个「当前值」；存在两个出处且冲突时，按事实源分权判定，并把冲突写进缺口清单。
2. 出处写法：相对路径 + 行位，或当场命令原文。不写绝对路径、主机名、端口、账号。
3. 找不到 → `未验证`；`未验证` 字段驱动的结论一律标「未验证模式」，不产出「通过」。
4. 用户口述只能作为「待确认」来源；确认后才升为出处。
5. profile 变更要连同出处一起改；只改值不改出处视为无效。

## 最小可用 profile

- 允许进入实现：验证命令、测试命令、文档根、决策人角色四项非「未验证」。
- 允许进入交付：验收清单、验收人角色、证据有效期三项非「未验证」。
- 只读咨询类任务：可全部未验证，但结论必须带「未验证」标记。

## 反例

- 从其他项目复制一段命令清单，未核对本项目脚本存在性。
- 把「团队口头约定」写成正式判据。
- 把看板里的数字当验证命令的输出。
