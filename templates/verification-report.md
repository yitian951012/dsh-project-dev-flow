# 验证报告：{{project.name}}

> 用法：**先写结论，再写证据**。每条「通过」必须能回答：跑了什么、退出码多少、在哪个提交上跑的。
> 结论口径分两层：**总结论**只允许三种（候选完成 / 不通过 / 未验证）；**逐条判据**允许四种（通过 / 失败 / 未验证 / 降级验证）。降级项必须在「未覆盖与不稳定」里写明降级原因。

## 1. 结论

| 字段 | 值 |
| :--- | :--- |
| 结论 | 候选完成 / 不通过 / 未验证 |
| 提交 | {{commit:head}} |
| 采集时间 | {{date:today}} |
| 工作区是否干净 | 是 / 否（含未跟踪文件） |
| 判级依据 | 逐条对应验收行 |
| 签认状态 | 待 {{role:approver}} 签认 |

## 2. 环境

| 项 | 值 |
| :--- | :--- |
| 运行时版本 | 待填 |
| 依赖安装方式 | 待填 |
| 网络 / 外部服务 | 已连通 / 离线 / 未验证 |
| 数据状态 | 空库 / 样例数据 / 生产副本（禁止） |

> 环境未就绪时不得把失败记成通过，也不得把「跳过」记成「通过」。

## 3. 执行矩阵

| 层 | 命令 | 结果 | 退出码 | 覆盖内容 | 备注 |
| :--- | :--- | :---: | :---: | :--- | :--- |
| 静态 | {{command:verify}} | 待填 | 待填 | 类型与风格 | 待填 |
| 单元 | {{command:test}} | 待填 | 待填 | 业务逻辑 | 记录失败 / 跳过数 |
| 构建 | {{command:build}} | 待填 | 待填 | 可发布性 | 待填 |
| 端到端 | {{command:e2e}} | 待填 | 待填 | 用户路径 | 记录不稳定用例 |
| 守卫有效性 | 项目变异检查 | 待填 | 待填 | 检查器本身的判别力 | 见不变量方法 |

## 4. 未覆盖与不稳定

| 项 | 原因 | 影响 | 处置 |
| :--- | :--- | :--- | :--- |
| 待填 | 环境 / 时间 / 授权 | 待填 | 已登记 / 已排除并写理由 |

规则：

1. **不稳定用例不放过**：同一用例两轮结果不同，结论至少降为「不通过」并单列。
2. **跳过不等于通过**：跳过项写清原因，并计入未覆盖。
3. **证据不跨提交**：任一门禁在 {{commit:head}} 之前跑的结果不得拼进本报告。
4. **证据有效期**：超过 {{evidence:ttl}} 的证据自动失效，需重跑。

## 5. 残余风险

| 风险 | 概率 | 影响 | 缓解措施 | 接受人 |
| :--- | :---: | :--- | :--- | :--- |
| 待填 | 高 / 中 / 低 | 待填 | 待填 | {{role:approver}} |

## 6. 签认

| 项 | 内容 |
| :--- | :--- |
| agent 产出 | 本报告正文与证据 |
| 签认人 | {{role:approver}} |
| 签认方式 | 在项目自己的签认记录中登记 |
| 签认前必须确认 | 证据可复现、残余风险已知情、范围豁免已列明 |

> agent 只能起草本报告；签认是不可代理的动作。若项目有显式代理签认策略，须单独记录策略来源与责任归属，不能默认适用。
