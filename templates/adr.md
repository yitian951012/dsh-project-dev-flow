# ADR-NNN：标题

> 用法：ADR 记录**不可轻易反转**的决定。能靠改配置解决的事不写 ADR。
> 状态流转：提议 → 接受 → 已被替代（写替代者编号）→ 废弃（写原因）。

## 1. 状态与元信息

| 字段 | 值 |
| :--- | :--- |
| 编号 | ADR-NNN |
| 状态 | 提议 / 接受 / 已被替代 / 废弃 |
| 日期 | {{date:today}} |
| 决策人 | {{role:approver}} |
| 关联决策 | 待填 |

## 2. 上下文

- 现在的结构约束（已有表、已有契约、已有守卫）：
- 触发变化的场景：
- 不改会怎样：

## 3. 决策

一句话陈述：**我们决定 ______，因为 ______。** 边界必须写清：

| 边界 | 内容 |
| :--- | :--- |
| 做什么 | 待填 |
| 明确不做 | 待填 |
| 适用范围 | 待填 |
| 失效条件 | 出现什么情况时本决策应被重新审视 |

## 4. 备选方案与取舍

| 方案 | 优点 | 缺点 | 为什么没选 |
| :--- | :--- | :--- | :--- |
| A | 待填 | 待填 | 待填 |
| B | 待填 | 待填 | 待填 |

## 5. 后果

| 类型 | 说明 |
| :--- | :--- |
| 正向后果 | 待填 |
| 负向后果 | 待填 |
| 迁移影响 | 数据 / 接口 / 调用方 |
| 回滚路径 | 迁移档位、备份方式、回滚步骤 |
| 新增不变量 | 需要被守卫的约束 |

## 6. 验证

| 项 | 内容 |
| :--- | :--- |
| 自动断言 | 待填（测试或守卫名） |
| 人工核对 | 待填 |
| 证据位置 | 命令 + 退出码 + {{commit:head}} |
| 复核到期 | 待填 |

## 7. 收据

> 「已实施」不等于「已生效」：收据要证明运行时真的走了新路径。

| 项 | 内容 |
| :--- | :--- |

| 提交 / 采集时间 | {{commit:head}}；{{date:today}} |
| 观察到的运行时路径 | 日志、输出或收据记录位置 |
| 核对人 | {{role:approver}} |
