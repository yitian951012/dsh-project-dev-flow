# 项目状态看板：{{project.name}}

> 本文件是**当前状态的唯一入口**，但它是投影，不是独立事实源。
> 每格数字必须带「复现方式 + 采集时间」；没有复现方式的数字一律标「未验证」。

## 1. 阶段门禁

| 阶段 | 状态 | 交付物 | 通过依据 |
| :--- | :---: | :--- | :--- |
| 需求定稿 | 未开始 / 进行中 / 通过 | 需求与决策 | 决策编号 |
| 设计定稿 | 未开始 / 进行中 / 通过 | 架构与 ADR | ADR 编号 |
| 实现 | 未开始 / 进行中 / 通过 | 代码与测试 | 命令输出 |
| 验证 | 未开始 / 进行中 / 通过 | 证据包 | 报告位置 |
| 交付 | 未开始 / 进行中 / 通过 | 候选交付物 | 签认记录 |
| 复盘 | 未开始 / 进行中 / 通过 | 案例与改进项 | 案例与改进项已登记 |

> 只允许三态加「通过」，不写「基本完成」。部分完成就是「进行中」。

## 2. 事实源（数字只在这里）

| 维度 | 当前值 | 复现方式 | 采集时间 |
| :--- | :--- | :--- | :--- |
| 结构规模 | 待填 | 由项目命令统计 | {{date:today}} |
| 测试规模 | 待填 | {{command:test}} | 未跑 |
| 门禁状态 | 待填 | {{command:verify}} | 未跑 |
| 覆盖率 | 待填 | 项目覆盖率命令 | 未跑 |

规则：

1. 与本节冲突的其他数字一律以本节 + 当场输出为准。
2. 采集时间必须是最近一次真实执行；复制旧值视为缺陷。
3. 两种口径（声明数 / 运行数）必须注明用的是哪个。

| :--- | :--- | :---: | :--- |
| 待填 | 待填 | 已落地 / 部分 / 未开始 | 待填 |

## 4. 当前缺口

| 缺口 | 用户可感知影响 | 处置 |
| :--- | :--- | :--- |
| 待填 | 待填 | 已排期 / 已登记不做 / 待裁决 |

## 5. 维护约定

1. 状态必须由可复现命令支撑，禁止凭印象填写。
2. 历史轮次的数字不进本表；要留痕就写进历史文档并标注时点。
3. 看板与索引分工：看板管「到什么程度」，索引管「有哪些文档」。
4. 每次更新看板时，同时复核决策台账里未关闭的项。
