# 项目开发流程

## 简介

安装本插件后，你的 DSH 会增加三个实用能力：

1. **「项目开发流程」会话模式**：让 Agent 按「需求受理 → 设计定型 → 实现 → 验证 → 交付 → 复盘」推进工作，每条结论都附带实际命令或文件证据，不替你拍板或签字。
2. **输入框快捷面板**（`3.0.1`）：点击输入框左侧的流程图标，可以一键新开流程会话，或把 5 个阶段技能的 `/命令` 插入到草稿首行（不会自动发送）。
3. **侧栏「项目看板」**（`3.0.0`）：只读展示从项目 `docs/` 自动汇总的阶段进度、待办、待裁决与阻塞项。

## 五个技能入口

前 3 个技能会在对话中自动按需启用，后 2 个只能在需要时通过 `/命令` 手动调用：

| 技能命令 | 适用场景 | 触发方式 |
| :--- | :--- | :--- |
| `project-dev-flow` | 接手陌生项目、跨阶段推进复杂任务 | 自动 / 手动 |
| `project-intake` | 收到新需求、变更或缺陷，需要明确范围与验收标准 | 自动 / 手动 |
| `project-docs` | 文档散乱、需要建立索引或排查文档与代码不一致 | 自动 / 手动 |
| `project-acceptance` | 准备交付、核对验收清单、检查证据是否过期 | 仅手动 |
| `project-case-distill` | 将一次真实交付或排障过程沉淀为复用案例 | 仅手动 |

手动调用示例：`/project-acceptance 帮我核对这次能不能交付`

> 提示：这 5 个技能只在「项目开发流程」模式下生效，因此在普通会话中，输入框面板里的技能按钮会处于禁用状态。

## 环境要求与安装

- **DSH 版本**：`>=0.2.3-alpha.2 <0.3.0-0`（已校验运行时：`0.2.3-alpha.2`；`0.2.2` 及更早版本不支持侧栏看板）
- **Node.js 版本**：`^24.22.3 || >=26.13.1`

### 安装方式

- **安装 3.0.x（含看板与输入框入口）**：`3.0.x` 目前尚未发布到 npm，请在 Plugins 面板选择「本地目录安装」并指向本包目录，或通过 GitHub 安装：
  `dsh plugin --profile <profile> add github:yitian951012/dsh-project-dev-flow`
- **通过 npm 安装（当前为 2.1.3，不含看板）**：
  `dsh plugin --profile <profile> add @yitian951012/dsh-project-dev-flow`

### 上手步骤

1. 安装并启用插件后，**新开一个会话**（已打开的旧会话不会切换模式）。
2. 在模式选择器中选择 **「项目开发流程」**。
3. 如需使用项目看板，可在项目根目录运行 `node scripts/import-board.mjs --root <项目路径>` 生成看板数据，然后在侧栏打开「项目看板」。

升级时请先移除旧包再安装新包；卸载后插件自带技能和模式会一并移除，不会影响项目自己的 `.dsh/skills` 或 `.agents/skills`。

## 使用边界

1. **项目规范优先**：如果项目已有自己的工程手册或同名技能，优先遵循项目自身的约定。
2. **人不缺位**：范围、契约变更与最终验收签字必须由人确认，Agent 只负责整理和起草。
3. **如实标注未验证项**：缺少测试命令或未实际跑通的检查，会直接写明「未验证」。
4. **看板当前为只读**：3.0.x 版本的看板与 `project_board` 工具只读取展示，不会改写你的 `docs/` 文档。

## 常用维护命令

```bash
npm run validate       # 校验包结构、链接与内容规范
npm run check:sources  # 检查源文档是否发生变更
npm run check:patch    # 校验 bundle patch 配置
npm test               # 运行单元测试
npm run verify         # 一键执行全部检查与打包预演
```

> 详细变更见 `CHANGELOG.md`，从旧版本升级请看 `MIGRATION.md`。
