# 历史留痕与案例沉淀

> 用途：把「当时发生了什么、为什么判断错了、留下了什么」写成可复用资产，同时不让历史冒充现状。

## 1. 适用与不适用

| 适用 | 不适用 |
| :--- | :--- |
| 一次实测、一轮修复、一次交付、一次事故要留痕 | 需要当场证据来判断当前状态 |
| 要把失败过程沉淀成可复用的判断 | 只想记录一个好消息（那属于公告） |
| 要合并重复的历史快照或迁移宿主 | 要新增一份「最佳实践」清单 |
| 要判断某条旧结论还能不能用 | 要据此修改验收判据（那需登记决策） |

边界：本文件产出「证据与背景」，不产出「当前结论」。任何当前判断都必须回到当场证据。

## 2. 核心判断

1. **历史是证据，不是现状。** 历史结论只能作为背景解释，不能作为当前判定依据；把旧结论当今天的事实，是最常见也最难纠正的错误。
2. **一次记录就是一份时点快照。** 其中的数字、路径、结论只对那个时点成立。写作时就按「这是快照」来写，而不是按「这是事实」来写。
3. **追加式维护，不回改。** 新认识以新增小节表达，旧行保留原样；回改历史行等于篡改证据链，读的人再也无法复原当时的判断。
4. **合并不删字，先问能否并入。** 遇到同类快照先问「能否并入已有宿主」，减少独立成篇；合并只换宿主，标题下移、旧文件名留作链接文字，并登记旧名到新宿主。
5. **案例的价值在错误判断。** 只写「我们做得很好」的案例价值为零。必须写当时的错误判断，以及这段经验不可外推的边界。
6. **失败过程比结论重要。** 背景与约束、错误判断、候选方案与实际取舍、可观察证据、修复后的残余风险——五项齐全，案例才可复用。
7. **复盘必须挂可执行落点。** 结论要落到守卫、检查项、流程改动或模板字段上；没有落点的写「未落地」，否则它只是散文，而散文不改变行为。
8. **脱敏是硬要求。** 不写绝对路径、主机名、账号、密钥、真实作品与客户；来源统一写「来源项目（下称 P）+ 日期 + 事件」，原文不随包发布。
9. **归档只作证据链。** 归档性质的内容不作任何判断依据；它可以被引用来说明「当时查过什么」，不能被用来证明「现在是什么」。
10. **措辞守时态。** 历史文档里不得用现在时描述今天；引用历史时必须带时点，例如「某时点曾达成」而不是「已达成」。

## 3. 可执行步骤

1. **判类型。** 这次记录属于哪一类：单次实测留痕 / 轮次进展 / 交付时间线 / 审计归档 / 失败案例。类型决定写多细、放在哪。
   产出：类型判定 + 一句话理由。
2. **选宿主。** 先查现有合集与主题：能并入就并入（按主题或按时间分节），不能并入才新建独立篇。
   产出：宿主决定；新建时写明「为什么不并入」。
3. **写时点与环境。** 记录时间、复现环境、方法、以及本轮明确**没有**做什么（未覆盖比覆盖更容易被忽略）。
   产出：时点、环境、方法、未覆盖清单。
4. **写结论与去向。** 每条结论后面跟一句「现在去哪看」，把读者导向当前源，而不是让旧结论留在真空里。
   产出：结论 + 去向指引。
5. **按七段写案例。** 背景与约束 / 当时的错误判断 / 候选方案与实际取舍 / 可观察证据（命令类型、结果量级、时点）/ 修复后残余风险 / 可提炼方法 + 不可外推边界 / 与方法的链接。
   产出：案例全文；缺第 2 段或第 6 段不予收录。
6. **脱敏自查。** 逐项检查路径、主机、账号、密钥、真实作品与客户；外部作品只作机制描述，不引原文。
   产出：自查清单（全部为「已清」或有理由的保留）。
7. **登记。** 追加登记行（日期、依据、去向）；涉及合并时登记旧名到新宿主；同时确认索引里的性质归属。
   产出：登记行 + 索引性质；两者不一致即视为漂移。
8. **落点化。** 把可复用判断转成守卫、检查项、流程改动或模板字段，并写明落在哪个位置。
   产出：落点清单；无落点则标「未落地」并列入待办。
9. **回看。** 当被引用方法或现状发生变化时，回看旧案例是否仍成立，并在案例里追加「复核注记」，不改原文。
   产出：复核注记（时点 + 结论是否仍成立）。

## 4. 常见失败

| 失败 | 表现 | 纠正 |
| :--- | :--- | :--- |
| 历史当现状 | 用旧结论描述今天 | 引用必带时点，现状回源 |
| 回改历史行 | 为了让文风统一而重写旧条目 | 追加新小节，旧行不动 |
| 合并丢字 | 合并时压缩或删句 | 原文保留，只换宿主 |
| 快照独立成篇 | 每轮实测都新开一篇 | 先问能否并入现有合集 |
| 案例只写结论 | 通篇「效果很好」 | 补错误判断与不可外推边界 |
| 证据只有形容词 | 「大幅改善」无任何量级 | 写结果量级与时点 |
| 教训无落点 | 记了一条教训，机制没变 | 转成守卫或检查项，或标「未落地」 |
| 脱敏靠印象 | 路径与账号散落正文 | 逐项自查后再提交 |
| 性质双重归类 | 同一份既算活又算史 | 性质只在一处登记 |
| 归档被当依据 | 引归档文档证明当前状态 | 归档只谈「当时查过什么」 |
| 旧名失链 | 合并后仍有人引用旧文件名 | 登记映射，并在入口处指引新宿主 |
| 现在时写历史 | 「系统支持 X」写在时点文档里 | 改成「当时支持 / 当时观察到」 |
