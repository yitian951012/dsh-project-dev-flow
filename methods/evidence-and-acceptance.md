# 证据链与验收判定

> 用途：把「做到哪一步了」从感觉变成证据，并给出降级规则。本文件只给判定协议，不给任何项目的命令与数字。

## 1. 适用与不适用

| 适用 | 不适用 |
| :--- | :--- |
| 要判定某个范围做到哪一级、凭什么 | 只是继续开发，还没到判定时点 |
| 证据不足、过期或自相矛盾，需要降级 | 需要现场实测（那要先跑，再回来判） |
| 要区分「未验证 / 未通过 / 环境未就绪」 | 要决定签不签收（那是人的动作） |
| 要判断某项「已完成」的声明是否成立 | 只看测试是否全绿（那是执行，不是判定） |

边界：本文件判「证据够不够」，不判「功能好不好用」。好用与否属于产品判断，不因证据充分而自动成立。

## 2. 核心判断

1. **级别由证据决定，不由声明决定。** 任何「已完成 / 已通过」的句子，先问它背后有没有当场证据；没有就降级，不看作者是谁。
2. **证据下限三件套：复现入口 + 退出码 + 载体标识。** 三者缺一即「未验证」；完整六要素（再加入判据编号、时间、输出摘要）见 `skills/project-acceptance/references/evidence-chain.md`。只说「跑过了」不算证据。
3. **门控只降不越。** 缺一项就判在实际满足的最高级；不得用「其余都很好」「上次也是绿的」抵消缺项。
4. **证据绑当次载体与时间。** 换载体或超过约定有效期即自动失效；他人文档里的数字是转引，不是证据。
5. **不许自证。** 五种自证要一律作废：自己改判据、把收集数当通过数、把检查器绿灯当内容正确、拿历史基线当本次证据、把「代码里有」当「已经生效」。
6. **「未验证」是合法的交付状态。** 没跑就写「计划，未跑」；禁止「应该没问题」这类措辞，也禁止把未验证项计入通过数。
7. **通过数必须与收集数同源。** 判定看三件事：通过数等于收集数、失败数为零、跳过数为零。只看「没有失败」会漏掉「没跑」。
8. **未就绪与被拒必须分开。** 工具要能给出独立的「环境未就绪」信号；环境问题不得算成通过，也不得算成功能失败。
9. **人工项单列，不得代签。** agent 只起草证据包，签认留痕到人。代理签认只能是项目级显式策略，并且必须写明授权来源。
10. **稳定性即门槛。** 「重试才过」按红处理，不用「负载高」「偶发」解释掉；能容忍的抖动要写成明确阈值，不能靠体感。
11. **未覆盖要写边界。** 每条未覆盖项写清原因、替代覆盖方式、为什么不再扩张。假装全覆盖比承认缺口危险得多。
12. **口径差要声明。** 静态计数与运行收集常不相等；同一份判定只能用一个口径，并且写明用的是哪个。

## 3. 可执行步骤

1. **定级别与硬证据。** 从低到高给每一级列「全部成立才算数」的证据清单；证据必须是可复现的入口，不是描述。
   产出：级别 → 证据清单表（含每项的反例要求）。
2. **定唯一序列。** 一次判定只用一组固定顺序的检查；序列写在一处并作为唯一清单，避免「同一个级别在不同文档里是不同的证据组」。
   产出：判定序列（顺序 + 判据 + 失败即降级）。
3. **取干净起点。** 先确认工作区无未提交改动，再取载体标识与时间；在脏工作区上取得的证据不作数。
   产出：载体标识 + 时间 + 工作区状态。
4. **按序列跑并留原始行。** 只采信当场输出的汇总行；文档里的旧数字、他人转引一律不作证据。
   产出：每道检查的原始汇总行。
5. **填空表只填本轮值。** 缺项写「未评估」，不写「通过」；旧快照保留但标明时点，不得与新值混合成一张表。
   产出：本轮判定表（每行一个值 + 时点）。
6. **过门控。** 逐项检查：缺证据、通过数小于收集数、判据被动过、证据来自别的载体、只有人工目测。命中即按降级规则处理。
   产出：降级动作与最终级别。
7. **查自证。** 看本次改动是否触及判据、基线、白名单、跳过范围；触及则要求授权与「改坏 → 变红 → 改回」记录，否则当次绿灯作废。
   产出：判据改动清单 + 授权与变异记录（若有）。
8. **写覆盖边界。** 列未覆盖项、原因、替代覆盖，并声明本轮不扩张的理由。
   产出：未覆盖清单；不得写成「已知限制」一句了事。
9. **同载体二次复跑。** 同一载体上再跑一次，比较两次结果；不一致即说明存在不稳定项，先定位再判级。
   产出：两次结果对照。
10. **给结论。** 结论句写成「候选完成 + 证据链 + 剩余风险」；人工项单列待签，剩余风险书面接受。
   产出：判定结论 + 待签清单 + 剩余风险。

## 4. 常见失败

| 失败 | 表现 | 纠正 |
| :--- | :--- | :--- |
| 只列不跑 | 用「会被执行」的清单当通过 | 只读汇总行，通过数须等于收集数 |
| 拿旧数字当证据 | 引用文档里上一次的数字 | 每个数字从当场输出取原值 |
| 证据没绑载体 | 「已验证」后面没有载体与时间 | 补载体；补不上就降级 |
| 证据过期仍在用 | 早已超出约定有效期 | 到期自动失效，重新跑 |
| 判据被顺手改 | 阈值被调宽、白名单被加条目 | 授权 + 变异记录，否则绿灯作废 |
| 分母硬编码 | 分母不变，新增用例后仍报满分 | 分母由计数推导并断言总数 |
| 只跑静态不跑构建 | 半截产物被当成真实运行结果 | 判定前必须有一次真实构建 |
| 环境未就算通过 | 工具跳过，退出码却是 0 | 区分「未就绪」并计为未验证 |
| 抖动被解释掉 | 「全量负载下偶发」当成可接受 | 重试才过即红 |
| 人工项混进自动 | 目测结论写进自动判据 | 单列为人工项，标「需人签」 |
| 覆盖假装完整 | 未覆盖项一句「已知限制」带过 | 写原因、替代、不扩张理由 |
| 口径混用 | 同一文档里声明数与运行数交替出现 | 固定一个口径并注明展开差异 |
