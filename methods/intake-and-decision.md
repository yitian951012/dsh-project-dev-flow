# 需求受理与决策登记

> 用途：在开工前把「要不要做、谁定、按什么算过了」定下来。本文件只给分类、字段与停止面。

## 1. 适用与不适用

| 适用 | 不适用 |
| :--- | :--- |
| 新需求、变更请求、缺陷反馈第一次进队列 | 任务已在受理单内，只需按单执行 |
| 要判断这次改动属于哪一类、门禁轻重 | 判据、范围、决策人都已定，只等执行 |
| 要判断是否必须停下来等人拍板 | 人员已授权且登记已完成 |
| 要把「不做」与「暂缓」分开记账 | 只做优先级排序（那是排期问题） |

边界：本文件决定「这件事怎么被受理」，不决定「这件事值不值得做」——价值判断属于产品取舍。

## 2. 核心判断

1. **先分类，再定门禁。** 分类错，后面全是白工：把契约变更当缺陷修，会漏掉跨端兼容；把判据变更当缺陷修，等于自己改尺子。
2. **按影响面分类，不按工作量分类。** 改一行对外契约比改一百行样式更重。分类看的是「动了谁的行为、谁的契约、谁的数据、谁的尺子」。
3. **判据先行。** 没有「可失败的判据 + 复现入口 + 至少一条反例」的需求不算受理完成。只有目测项时必须标为人工项，不得混进自动判据。
4. **决策先于实现。** 改变已登记行为、契约、数据、判据或范围时，先登记决策再动代码。顺序反了，既成实现会反过来绑架决策。
5. **一个决策只有一个当前编号。** 旧编号只作别名。同一件事出现多套编号时，读者会按错误的编号理解结论——这不是笔误，是编号体系缺失。
6. **「已决」必须能拆成三段。** 拍板了、落地了、被推翻了是三种状态。混成一个「已决」，验收时必然对不上，实现欠账也会消失。
7. **agent 起草，人签认。** 范围、判据、契约、数据、凭据、对外发布这些归属人的决定，起草与签认必须分离；只有项目级显式策略才可例外，且那是项目选择不是默认流程。
8. **不做清单与待办清单互斥。** 同一事项不得两处各记一次，否则会出现「已决定不做，又在新待办里复活」的双重记账。
9. **失效条目不删、编号不复用。** 决策被后续实现推翻时保留编号与原文，改述为「当时结论 + 现在实际」，并写明重启条件。
10. **队列分三类收口。** 已闭环、需人拍板、仍可推进。需人拍板的不要再派执行方「复核」——复核不会改变「等人」这个状态，只会把队列变成永动机。
11. **「不做」不等于「做不到」。** 多数「不做」是投入产出不划算或已有更简单的替代。写「不做」必须同时写替代方案与重启条件，否则它半年后会变成一句无人能解释的禁令。

## 3. 可执行步骤

1. **收原文。** 记录需求原话、来源、提出时间；转述过的要标注「转述」，不得当成原始依据。
   产出：需求原文块（原话 / 来源 / 时间 / 是否转述）。
2. **判类。** 按影响面命中一类：缺陷修复 / 新能力或行为变化 / 契约变更 / 数据操作 / 判据与基线变更 / 范围扩张 / 文档与流程。命中多类取最重，其余作为并列约束。
   产出：类别 + 依据句（动了哪个面）。
3. **查不做清单。** 命中已登记的不做项时，只有满足重启条件才可继续；否则返回「不重启」并留一句理由，不重复论证。
   产出：命中行 + 是否满足重启条件的判断。
4. **过停止面。** 改判据阈值、改基线白名单、改契约、做数据操作、扩范围、新增或修改决策、发布对外能力——任一命中先停，起草决策条目。
   产出：停止面命中清单，未命中则写明「不触发」。
5. **填受理单。** 字段以 `skills/project-intake/references/intake-checklist.md` 的九项必填为准，逐项填写并标缺项；缺任一项即不得开工。
   产出：受理单；缺任一项即不得开工。
6. **过检查清单。** 目标用户与路径落点、事实与假设分离、不做的代价能否映射到主路径、指标是否复用既有口径、判据是否可失败、该登记的决策是否已登记、数据类是否有回滚、是否触碰红线、优先级是否落在主路径上。
   产出：逐项结论（通过 / 不通过 / 需人定）。
7. **登记。** 决策条目写编号、决定内容、状态、日期、原始拍板出处、影响面；先登记再改实现，实现欠账记在影响面里。
   产出：登记行；无登记行则不得进入设计定型。
8. **分流。** 把队列分成已闭环 / 需人拍板 / 仍可推进，并对后两类各给一句「下一步谁动」。只推进「仍可推进」那一类。
   产出：分类后的队列视图。

## 4. 常见失败

| 失败 | 表现 | 纠正 |
| :--- | :--- | :--- |
| 未登记先实施 | 行为已变，登记里没有对应行 | 先补登记，再留实现欠账 |
| 按工作量分类 | 用代码行数估计影响面 | 按行为、契约、数据、尺子四个面估 |
| 判据自改 | 为让结果变绿把门槛改成「无新增失败」 | 判据变更须登记 + 反向验证 |
| 多套编号 | 同一决策在不同处有三个名字 | 收敛到一个编号，其余降为别名 |
| 双重记账 | 同一事项既在不做清单又在待办 | 选一处记，另一处只留引用 |
| 已决当完成 | 决策写着已决，代码里没落地 | 状态拆成拍板 / 落地 / 推翻 |
| 顺手扩范围 | 「反正一起做了」 | 扩范围不计进度，退回受理 |
| 起草即自批 | 起草者自己签了决策 | 起草与签认分离，签认留痕到人 |
| 判据只有结论 | 写着「应无异常」，没有命令也没有反例 | 补复现入口与反例，否则标「未验证」 |
| 队列永动机 | 每轮都重写同一批「待裁决」 | 拆成三类，只推进可推进那类 |
| 受理单缺回滚 | 数据类改动没有备份与回退路径 | 补回滚方式，缺则不开工 |
| 用转述当原文 | 二手描述被当成需求本身 | 标注转述并回找原话 |
| 不做项无重启条件 | 半年后没人知道为什么不做 | 补替代方案与重启条件，否则移出清单 |
